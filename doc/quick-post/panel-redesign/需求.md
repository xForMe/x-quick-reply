# 快速发帖面板视觉重构

## 目标

重构 X 发帖场景中的快速发帖侧边面板，解决截图中“面板窄、内容挤、主次操作不清、候选帖文难读”的问题。保持现有发帖流程、缓存语义和人工发布边界不变，只改善信息层级、卡片布局、状态反馈和可访问性。

## 已确认的问题

- 截图中的面板固定在 X 页面右下角，宽度有限，长帖文被压成多行，阅读和比较成本高。
- “生成新一批”“改用热门推文榜”“清空缓存”等动作视觉权重接近，用户难以判断当前最主要的下一步。
- 当前状态、候选缓存、来源话题、核实提示和操作按钮连续堆叠，缺少明确的阶段分隔。
- 候选帖文卡片的正文、来源和核实提示没有稳定的阅读顺序。

以上是基于用户截图和当前 `content.js` / `content.css` 的确认；“不好看”本身是用户评价，不作为技术事实单独使用。

## 使用者与场景

- 使用者：在 X 发帖弹窗或 `/compose/post` 页面中使用发帖助手的账号运营者。
- 空缓存：首次打开面板，需要生成一批候选。
- 生成中：正在获取榜单、决策话题和生成帖文，面板不能重复触发。
- 有缓存：按来源话题分组查看候选，每次只将一条填入草稿。
- 已填入：当前候选已进入 X 草稿，用户仍需人工检查并点击 X 的发帖按钮。
- 失败：榜单、模型、缓存或回填阶段失败时，面板必须说明失败阶段和恢复动作。

## 范围

### 包含

- 面板宽度、内边距、颜色、字体层级、卡片和按钮层级。
- “生成新一批 → 缓存池 → 填入草稿”三阶段进度表达。
- 按来源话题分组的候选卡片，放大帖文正文，核实提示降级为信息块。
- 空态、加载态、成功态、已填入态和失败态。
- 生成来源切换的次级呈现、缓存清空的次级呈现和清晰的人工发布提示。
- 键盘焦点、语义标签、最小点击区域和减少动效支持。

### 不包含

- 不改变 xzhishu 数据源、模型接口、缓存上限、候选字段或错误阶段。
- 不新增自动发帖、复制到剪贴板、定时发布、批量发布或自动切换数据源。
- 不改变“每个话题生成一条帖文”“一次只填入一条”“人工点击 X 发帖”的业务边界。
- 不把截图中的演示文案当作真实榜单或模型结果。

## 验收标准

1. 原型可直接打开，展示空缓存、生成中、有缓存、已填入、失败五种状态。
2. 原型明确表达当前主操作只有一个：空缓存时生成，有缓存时填入草稿。
3. 候选卡片按来源话题分组，帖文正文可读，来源、核实提示和状态有稳定层级。
4. “改用热门推文榜”“清空缓存”“删除”均为次级操作，并不会与主按钮抢视觉权重。
5. 已填入状态明确写出“未发送，仍需人工点击 X 发帖”，不制造自动发布错觉。
6. 失败状态包含失败阶段、原因和明确恢复路径，不把失败显示成空缓存或成功。
7. 遵循 `$ui-ux-pro-max`：文本对比度、键盘焦点、语义状态、44px 主要操作命中区、无 emoji 结构图标、减少动效。
8. 技术方案明确哪些是现有代码事实、哪些是视觉判断、哪些仍需真实 X 页面验证。
9. 设计评审通过后，只修改 `content.js`、`content.css` 和原型文案，不修改发帖网关契约。

## 评审结论

用户已确认接受：

1. 面板宽度从当前约 320px 增加到约 420–440px。
2. “生成新一批”作为唯一主按钮，来源切换降级为次级操作。
3. 候选卡片按“话题标题 → 帖文正文 → 核实提示 → 操作”展示。
4. 面板顶部显示三步流程。

用户补充的视觉修改：

- 移除步骤“1 · 选话题”下方的“热榜 5 条”及其他步骤辅助小字。
- 移除面板底部“只填入草稿 · 不复制 · 不自动发帖 · 发布前请检查核实提示”整段说明。
- 移除“快速发帖”标题下的 `quick-post · 草稿工作区` 小字。
