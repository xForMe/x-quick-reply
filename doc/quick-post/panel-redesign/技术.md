# 快速发帖面板视觉重构技术方案

## 设计结论

采用“宽面板 + 阶段进度 + 话题分组卡片”的侧边工作区。视觉方向参考 `$ui-ux-pro-max` 的 Minimalism & Swiss Style 与 AI-Native UI 建议：高对比、克制装饰、明确主操作、使用紫色作为主行动色，青色作为来源和辅助状态色。

- 面板建议宽度：桌面 420–440px；小屏保留 100% 宽度并限制内容横向溢出。
- 面板表面：白色或近白色，使用边框和轻阴影与 X 页面分离，不使用大面积渐变。
- 内容层级：标题栏 → 三步进度 → 状态/主操作 → 缓存池摘要 → 话题组 → 候选卡片。
- 主操作：同一状态只保留一个视觉最高的按钮；来源切换、清空、删除为次级按钮或文本操作。
- 卡片：正文 15px 左右、行高 1.55；元信息和核实提示使用 12px；核实提示采用暖色信息块并配文字，不只使用颜色。
- 动效：仅使用短暂的 opacity/transform 反馈；尊重 `prefers-reduced-motion`。
- 面板标题只保留“快速发帖”；步骤卡片只保留三段主标签，不再显示“热榜 5 条”等辅助小字；底部不再放整段固定说明。

## 已确认事实

以下事实来自当前 `code/quick-reply/extension/src/content.js`、`content.css` 和 `doc/quick-reply/quick-post/技术.md`：

- 发帖面板由内容脚本中的 React 面板渲染，选择器入口为 `#quick-reply-panel`。
- 发帖模式当前显示“快速发帖”、状态文字、“生成新一批”“改用热门推文榜”、缓存池列表和清空缓存。
- 候选按 `sourceTopic` 分组；每个条目包含帖文正文、`checkNotes`、创建时间、推荐标记、已发过标记和未入缓存标记。
- 当前操作包括填入发帖框、放回可选、删除和清空缓存；插件不点击 X 的发帖按钮。
- 生成流程是获取榜单、决策/推荐、生成帖文、写入缓存；失败必须停止并保留失败阶段。
- 缓存上限、数据源、候选结构、回填 owned 规则和人工发布边界属于现有契约，本次不改变。

## 设计判断

以下内容是本次视觉与交互判断，不是现有代码已具备的事实：

- 面板从 320px 左右扩大到约 420–440px，减少长帖文被迫换行造成的比较困难。
- 用三步进度条表达“选话题 / 生成候选 / 填入草稿”，替代当前一段长流程说明。
- 空缓存时先展示解释性空态和单一主按钮；有缓存时将缓存摘要和候选列表提升到主内容。
- 来源切换只显示为次级操作，仍要求用户显式点击；不自动切换数据源。
- 话题组标题使用轻量分隔和计数，候选卡片用较大正文区域承载阅读，不把时间戳放在正文旁抢注意力。
- “清空缓存”放在缓存摘要行并使用低强调危险样式；删除保留在卡片底部的次级操作。
- 已填入条目突出“草稿已填入 / 未发送”，减少用户误以为插件已经发布的风险。
- 面板标题移除版本/工作区副标题，人工发布边界通过状态文案和既有流程表达。

## 模块边界

### `content.js`

- 保留 `QuickReplyPanel` 的发帖分支和现有 `data-action` 值，优先只调整 DOM 分组、文案容器和状态标记。
- 保留 `post-batch`、`post-batch-tweets`、`post-fill`、`post-unmark`、`post-delete`、`post-clear` 的行为与消息契约；来源切换后主按钮与次按钮根据当前来源互换 action 入口。
- 保持 `post-batch`、`post-batch-tweets`、`post-fill`、`post-unmark`、`post-delete`、`post-clear` 行为与消息契约不变。
- 继续使用 React 管理视图状态，缓存读写、网关调用和回填逻辑不迁移到视觉层。
- 失败信息仍来自现有 `props.status` / `props.statusError`；若新增阶段标签，只从已有状态或响应字段映射，不猜测接口结果。

### `content.css`

- 将当前 `#quick-reply-panel` 的宽度、边距、阴影和背景 token 化。
- 为 `.qr-cache-head`、`.qr-topic-group`、`.qr-cache-item`、`.qr-cache-check`、`.qr-cache-actions` 增加层级和响应式规则。
- 统一按钮最小高度、焦点环、禁用态、hover/pressed 状态。
- 不依赖外部字体、图标 CDN 或第三方脚本；结构图标使用内联 SVG 或纯 CSS。

## 交互契约

| 状态 | 主操作 | 辅助信息 | 依赖链 |
|---|---|---|---|
| 空缓存 | 生成新一批 | 数据源、三步流程、人工发布说明 | 不读取失败缓存替代空态 |
| 生成中 | 禁用生成按钮，显示当前阶段 | 进度和取消/停止语义按现有实现 | 不重复调用、不切换数据源 |
| 有缓存 | 填入发帖框 | 缓存条数、来源话题分组、核实提示 | 只填入空草稿或 owned 草稿 |
| 已填入 | 放回可选/换选 | “未发送，仍需人工点击 X 发帖” | 不点击 X 发帖按钮 |
| 缓存写入失败 | 保留现有失败动作 | 明确“本批未持久化” | 不显示已缓存成功 |
| 榜单/模型失败 | 允许按现有逻辑再次由用户发起 | 显示失败阶段和恢复说明 | 不自动重试、不换源 |

## 数据与隐私

- 不修改 `chrome.storage.local` 缓存结构、上限或字段。
- 不新增权限、密钥、服务商、接口或数据源。
- 不在面板、日志或诊断中显示密钥、Cookie、私信正文或完整模型响应。
- 帖文正文、核实提示和来源话题的显示范围沿用当前缓存边界；视觉改造不改变数据留存。
