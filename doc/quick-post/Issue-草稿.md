# Issue 草稿：发帖话题生成与候选缓存（quick-post）

## 标题

feat: 发帖模式——热榜选题、帖文生成与候选缓存

## 问题背景

账号运营需要定期发"吸引留言互动"的话题帖。人工流程是：参考热榜选角度 → 写带互动钩子的文案 → 发布前核对时效事实。2026-10-23 用该流程产出的 Codex 额度帖获得认可，希望固化为 quick-reply 的第二核心功能（发帖），与现有回复并列。

## 方案摘要（已评审 v4，2026-10-24）

1. 发帖模式无手动输入：从 xzhishu 热门话题榜取综合热度前 5 条（标题+摘要），百炼 decision-model-preview choice 定 1 条（可拒选）。
2. 基于选定话题生成恰好 5 条引互动帖文（≤280 字符），每条附 0–5 条发布前核实提示。
3. 候选进入缓存池（chrome.storage.local，跨会话）；每次选 1 条回填 X 发帖框草稿（唯一去向，无复制），人工点击发帖。
4. 换选不丢失：换下的候选自动放回；填入的条目标记"已发过"（不可再选，可放回）。
5. 缓存上限 30 条，满时自动清理：先删已发过的，再删最旧的。
6. 失败即停（暴露阶段与原因），不重试、不换源、不用缓存旧榜单替代；回复候选不缓存。
