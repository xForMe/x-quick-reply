# 发帖文案格式与口吻调整技术方案

状态：已评审并实现文本规则调整（2026-10-24）。真实模型输出和真实 X 页面仍待验收。

## 1. 信息分层

### 已确认事实

- 当前默认 `postPrompt` 要求帖文开头使用具体细节或反差钩子，结尾使用开放问题或低门槛选项。
- 当前 `prompts/post-policy.md` 也把“具体开头”和“互动问题/站队”写成统一帖文标准。
- 当前发帖候选已经支持换行显示，候选卡片使用 `white-space: pre-wrap`；本次主要改变生成规则，不改变缓存与回填契约。
- 当前流程是每个话题生成 1 条候选，候选进入缓存池，用户选择后只回填 X 草稿，插件不点击发帖按钮。
- 用户提供的第一张截图是用户自己的发帖样例：直接提问、连续追问、短段落、口语化标点、中英文产品名混用。这是本次应优先学习的个人口吻样本。
- 用户提供的第二张截图是他人样例：连续几段记录式陈述、每段一个意思。它只能作为结构参考，不能作为用户事实、措辞或固定口吻来源。

### 合理推测

- “AI 味”主要来自统一的写作结构和固定的互动收尾，而不只是句子是否通顺。
- 用户自己的历史发帖应作为主要风格证据；他人样例只能帮助说明段落节奏，不能直接喂入事实或措辞。
- 对这个用户，问题不是简单的“可选/不可选”：默认应允许自然的连续追问，但禁止把问题改写成营销式互动话术。

### 个人判断

- 默认规则应优先模拟用户的“直接问、补充判断、再追问”节奏，而不是把每条帖文都优化成转化文案。
- 生成器应避免为了互动而添加“评论区”“报数”“站队”等社交媒体话术；用户原本自然使用的“大家怎么觉得？”、“？？？”可以保留，但不能强行套用。
- 格式规则不宜固定每条都恰好 3–4 行，否则会形成另一种模板。建议使用 2–6 个短句行，并允许 2–4 个自然段。

### 待验证

- 真实模型在取消统一钩子/互动收尾后，是否仍能围绕话题写出具体、可发布的内容。
- 中文、英文和混合语言话题是否都能保持自然换行。
- X 实际时间线中，2–6 行和空行的阅读效果是否符合用户预期。
- 用户是否希望所有候选都带问题，或只希望问题不再被硬凑出来。

## 2. 方案

### 2.1 生成提示词

调整 `DEFAULT_POST_PROMPT` 与 `prompts/post-policy.md` 的帖文标准：

1. 默认先用用户口吻抛出一个具体问题或观察；不强制使用“钩子”这个写作术语。
2. 可按“问题 → 自己的判断/观察 → 实际追问”展开，但不要求每条完整走完；也可以写成连续记录式陈述。
3. 使用 2–6 个短句行，通常分成 2–4 个段落；只在自然停顿处换行，不拆碎完整语义。
4. 可以保留自然的口语标点和中英文产品名混用；禁止为了显得像真人而机械添加“？？？”、感叹号或网络梗。
5. 禁止套用“大家怎么看”“评论区聊聊”“报 1/2/3”“站队”等固定收尾；用户自己的问题句不等于这些模板。
6. 保留事实、隐私和语言跟随规则；用户没有提供的第一人称经历不能写成“我经历过”。
7. `postExamples` 继续作为可选风格样本，但在用户提供样例时应优先学习其句式、分行、口语标点和追问节奏，不复制事实。

### 2.2 输出校验

- 保留现有 JSON、候选数量、`topicId` 一一对应、字符上限和核实提示校验。
- 本次不新增“必须有问题句”“必须出现某个口语标点”或固定行数校验，避免把用户口吻再做成另一种模板。
- 不把输出失败改写成成功，不自动重写、不切换模型、不用旧候选替代当前结果。

### 2.3 设置页文案

发帖设置中的说明改为：

> 建议用你自己的历史发帖校准分行和口吻。默认优先模仿“直接提问、补充判断、再追问”的节奏，也允许连续几段记录式陈述；不会强行加“评论区”收尾。

保留用户可编辑的 `postPrompt` 和 `postExamples`，不新增密钥或服务商配置。

## 3. 模块边界与数据契约

- `settings.js`：更新默认发帖提示词文本。
- `prompts/post-policy.md`：更新生成标准和禁止项，与默认提示词保持同义。
- `service-worker.js` / `gateway.py`：接口字段、决策流程和缓存 schema 不变。
- `content.js` / `content.css`：本次不需要改变发帖面板布局；已有 `pre-wrap` 负责显示换行。
- `options.js`：只更新发帖设置的帮助文案；用户自定义提示词仍原样保存。

## 4. 错误与停止条件

- 话题获取、模型请求、JSON 解析、候选数量/长度或格式校验失败时，沿用现有阶段错误并停止依赖链。
- 不因为候选没有问题句就判定失败；不通过固定文案、旧缓存或重试“修复”模型输出。
- `postExamples` 为空是合法状态；示例不应成为生成成功的必要条件。

## 5. 验证计划与边界

### 自动化验证

- 更新默认提示词与策略文本的静态断言。
- 增加提示词和示例规则断言：用户样例用于学习分行、口语标点和追问节奏；有问题句和无问题句都不触发额外硬校验。
- 运行 `npm test` 与 `python -X utf8 -m unittest discover -s tests -v`。

### 真实验收

- 在真实模型上用至少三类话题观察：纯事实热点、产品/科技话题、日常观察话题。
- 在 Chrome/X 中检查候选卡片的换行、草稿回填和人工发布边界。
- 互动量不能作为本次改动已成功的自动化证据；只能作为后续观察数据。
