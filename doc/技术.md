# 技术设计

## 文件边界

Chrome 只加载 extension，其中包含 manifest.json 和 src/。Python 网关、.env、tests/ 和 __pycache__/ 留在工具根目录，防止缓存名称导致 Chrome 拒绝加载，也避免将模型配置放进扩展包。

## 两阶段流程

Chrome MV3 扩展 → Python 本地网关 → OpenAI 兼容大模型生成 2–5 条候选 → 阿里云百炼 decision-model-preview 选择 → 自动回填空输入框 → 用户检查并手动发送。

| 能力/组件 | 输入和来源 | 输出 | 权限、失败行为 |
| --- | --- | --- | --- |
| extract / content script | 当前帖子回复弹窗或具体私信 DOM | 公开回复为唯一目标帖完整可见正文；私信为最近可见最多 20 条、每条最多 800 字、总计 8,000 字 | 找不到唯一输入框、正文或会话边界时停止；私信身份无法识别时标为 unknown |
| orchestrate / service worker | 当前会话快照及扩展配置 | 完整候选及合法决策 | 校验发送者、URL、Schema、ID 和概率；生成失败不调用决策 |
| generate / gateway | 对话、语气、候选数量 | 代码分配 c1–c5 ID 的候选 | 只访问预配置生成服务，不切换供应商；非法或截断 JSON 整次拒绝 |
| decide / gateway | 同一对话和完整候选 | 选择、置信度、概率分布或拒选 | 百炼 System One choice，仅官方域名；全部不合适允许拒选 |
| fill / content script | 选中候选及原会话快照 | 输入框草稿 | 会话、消息、编辑框或草稿变化后停止，不覆盖原草稿，不发送 |

维护方为本项目维护者；账号、模型权限、凭据由本机使用者配置。无需引入 MCP、注册中心或多智能体循环。

## 本地 API：quick-reply.v2

网关仅监听 127.0.0.1，默认端口 8787。扩展使用 JSON 和 X-Quick-Reply: v1 请求头。网关校验 Host 与 chrome-extension://<32位ID> Origin，拒绝普通网页来源；允许同机其他扩展，不构成多用户鉴权，仅用于可信单用户机器。

POST /v1/replies/generate 请求：

- schemaVersion：quick-reply.v2。
- kind：必填 public-reply/direct-message，缺少或非法时报错；生成和决策提示均按该场景处理。public-reply 必须恰好一条 role=them 的目标正文，候选不超过 280 字符。
- messages：1–20 项，每项含 role（me/them/unknown）与 text（非空文本）。
- language：可选，默认 auto；0.2.5 起仅接受 auto，表示按正文主要语言回复。非 auto 报 400 并要求同步更新扩展/网关，不静默采用页面语言。
- tone：natural/concise/polite/professional。
- candidateCount：整数 2–5。
- replyPrompt：0.3.0 起必填，1–3000 字符；replyExamples 可选，最多 3000 字符。扩展设置提供显式首次默认值。网关拒绝缺失、空白、非字符串或超长，不隐式补全。

响应含 schemaVersion、candidates（id、text）及 meta（model、promptVersion、elapsedMs）。

POST /v1/replies/decide 在相同请求中附 candidates。响应含：

- selectedId：当前候选 ID；百炼选择 __none__ 时为 null。
- reviewRequired：拒选时为 true，停止回填并提示人工起草。
- confidence：百炼 Choice 原始置信度，0–1，不是回复正确率。
- probabilities：全部候选和 __none__ 的原始概率，和约为 1。
- model：decision-model-preview；elapsedMs：网关观测耗时；schemaVersion：quick-reply.v2。

不再使用初版原型的 score/reason。Choice 不生成自由文本理由；Score 是另一类问题，值域也不能一概解释为 0–1。插件不虚构理由或将置信度当成正确率。

GET /health 返回 schemaVersion、promptVersion 和缺失配置项名称，不返回密钥。错误含脱敏 error：400 请求错误，403 来源拒绝，503 配置缺失，502 上游或结构错误，504 网络/超时。

## 上游调用

生成服务：POST {LLM_BASE_URL}/chat/completions，使用 LLM_MODEL、LLM_API_KEY。请求 system/user messages、stream=false。默认不发送供应商可能不支持的 response_format；可配置 LLM_JSON_MODE=true 开启 json_object。只接受符合契约的纯 JSON；Markdown 包裹、截断、数量不符或无文本均拒绝，不修补、不兜底。候选 ID 由代码赋值，不依赖模型自报 ID。

百炼决策：按照 2026-10-17 官方资料核对：

- [决策模型 API](https://help.aliyun.com/zh/model-studio/decision-model-api)
- [模型信息](https://help.aliyun.com/zh/model-studio/decision-model-preview/)
- [Token Plan 指南](https://help.aliyun.com/zh/model-studio/token-plan-decision-model)

普通 API 地址为 https://{真实业务空间}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/systemone，新加坡可选 ap-southeast-1；使用 DASHSCOPE_API_KEY。Token Plan 使用 https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/systemone 和 BAILIAN_TOKEN_PLAN_API_KEY，不自动读取 ANTHROPIC_AUTH_TOKEN，不复用普通 Key。

请求含 model、state、questions.best_reply：type=choice，instructions 为字符串，criteria 为候选 ID 到正文的映射，加 __none__。按问题 ID 解析 answers.best_reply.choice/confidence/probabilities，校验模型、ID、分布和置信度。

## 配置与隐私

- 优先级：进程环境 > 工具目录 .env。直接填写具体配置项，不引用或读取其他配置文件；工具配置相对 gateway.py 解析，与启动目录无关。
- 生成模型填写 LLM_BASE_URL、LLM_MODEL、LLM_API_KEY；百炼普通 API 填写 DECISION_PROVIDER=bailian、BAILIAN_SYSTEMONE_URL、DASHSCOPE_API_KEY。Token Plan 填写专用配置，不混用凭据。
- 生成密钥与百炼密钥独立；生成服务未配置时不改用通义千问或 Mock。
- 对话和候选仅在内存处理，不写 chrome.storage、文件、访问日志或原始异常日志。
- 两个模型服务都会收到所选对话内容；本地网关不等于本地推理，服务商保留/训练政策尚未核实。
- 消息和候选是不可信数据，不得充当系统指令。提示约束不保证事实正确，用户仍需检查后发送。
- 上游校验 HTTPS 证书且不跟随重定向，仅本机生成服务可用 HTTP；百炼限制官方域名和固定路径。
- 默认每次上游超时 25 秒，无自动重试；扩展每次网关调用最大等待 100 秒。
- 当前 X DOM、平台规则和真实私信流程待验证；不将原型描述为已上线。

公开回复识别限定 /compose/post 或 /<用户>/status/<数字ID> 路由。0.2.0–0.2.2 要求全页面仅有唯一可见 role=dialog，已在 0.2.3 修正：从全页查找唯一可见且位于弹窗内的 tweetTextarea_* contenteditable textbox，沿其祖先确定最外层 role=dialog 边界，兼容同一弹窗的嵌套包装层，忽略没有编辑框的无关弹窗。在该边界内要求编辑器之前的唯一 data-testid=tweet 和唯一可见 tweetText；0.2.4 取消强制 status ID 的要求，原因及新快照契约见下节。不从背景页寻找替代帖子。已取得用户的结构计数诊断，尚无完整真实 DOM 或成功回填证据。

回填前比较路由、场景、正文、目标节点、编辑器及草稿；公开回复额外比较弹窗、正文节点引用和目标内链接列表。用户输入、关闭面板或路由切换会失效旧请求。0.2.8 的 contenteditable 写入协议及草稿替换规则见末节，已替换旧 insertText 编辑命令路径；绝不点击发送。私信无法确定 DMConversation/DmActivityViewport 边界时停止，移除全 document 读取路径。

## 0.2.1 初始化与通信修复

用户已加载 0.2.0，popup 报“当前页面未连接扩展”。该提示原本覆盖所有 tabs.sendMessage 异常，不能据此确认具体原因。自动化复现发现：旧代码在已有面板 DOM 时直接 return，不注册消息监听；innerHTML 在禁止 TrustedHTML 字符串赋值的环境下启动即失败。尚未取得用户真实控制台，不能宣称该页面一定触发了 Trusted Types。

工具栏点击流程调整为固定顺序：executeScript(ISOLATED, frameId=0, src/content.js) → 验证显式初始化结果和版本 → insertCSS → tabs.sendMessage(OPEN_QUICK_REPLY, frameId=0)。新增 scripting 权限，站点 host_permissions 范围不变；不增加 tabs、调试或浏览记录权限。保留导航时的静态注入，手动点击始终执行当前文档初始化，不是消息失败后的重试或降级路径。

插件面板、popup 和设置页使用 React 17 + ReactDOM 渲染，运行时以 extension/src/vendor 下的本地文件随扩展加载，不依赖远程 CDN 或额外构建步骤。React 只管理插件自己的 UI 状态；X 页面中的帖子、编辑器、发送按钮和点赞按钮仍通过原生 DOM 查询与事件监听读取，因为这些节点属于外部页面且会被 X 的 SPA 动态替换。每次显式初始化清理本工具之前的 React 根节点、监听和计时器，重新注册唯一监听；DOM 节点或全局标记均不作为当前扩展通信正常的证据。初始化错误返回 ok=false；React 运行时、注入、样式或连接失败保留原始错误并停止，禁止笼统提示重载后当作已修复。

## 0.2.2 操作状态修正

未发起生成时导航到回复弹窗显示普通点击说明；仅此前有请求或结果时导航才提示旧回复失效。蓝色按钮标明“生成并填入回复”，请求等待期间禁用并显示“生成中”，当前请求结束或失效后恢复；不可用的回填按钮隐藏。真实失败仍标红并停止，不改动模型流程、数据来源或回填校验。

## 0.2.3 结构诊断

错误状态提供“复制排查信息”，由用户主动点击后复制 quick-reply.dom.v1 JSON 到剪贴板。仅含场景类型、版本、节点标签/role、白名单 data-testid、可见性、aria 状态、弹窗和编辑框计数以及编辑器祖先层级。限制最多 12 个弹窗、6 个编辑框、每项 12 层祖先。不含 innerHTML、textContent、正文、草稿、链接、帖子 ID、用户名或配置；不上传、不持久化，不发送给模型。剪贴板操作失败明确报错，不切换数据来源或自动补选目标。

## 0.2.4 无帖子链接的回复预览

用户提供的 0.2.3 结构诊断显示两个 dialog、两个编辑器，但仅一个编辑器可见；每个 dialog 各有一个 tweet/tweetText，statusLinks 均为 0。此前从目标链接提取唯一 ID 是页面读取的强制条件，而目标 ID 并不在生成/决策网关请求中使用。此限制阻断正常的无链接预览，不能靠刷新修复。

公开回复的唯一契约改为当前弹窗中唯一可见目标正文及回复编辑器。所有回复统一快照记录弹窗、目标、正文节点、编辑器引用，以及 URL、正文、目标内链接列表和原草稿；链接列表允许为空，它是变化检测的元数据，不是正文来源。回填时重新读取并逐项比较，任一不符即停止；不从页面路由或背景信息流猜测 ID，不伪造 ID，不切换模型或数据源。节点引用和页面可见元数据不能证明平台后台身份，真实页面验收仍有必要。

quick-reply.dom.v1 增加可选结构字段：eligibleEditorCount、弹窗内可见编辑器/帖子/正文计数、编辑器所在最近及最外层 dialog 的数组索引。未找到的索引为 -1；保留原有数量上限与脱敏边界，不复制链接值。

## 0.2.5 回复语言

旧内容脚本把 document.documentElement.lang 作为回复 language，后台缺少此字段又设为 zh-CN，生成提示仅要求“参考”对话语言，与正文来源冲突。新版内容脚本和后台统一发送 language=auto，网关只接受该策略；不从界面或浏览器语言选择回复语言。

生成和百炼 choice 共享正文语言规则：公开回复以唯一目标帖正文为准；私信以当前待回复消息为准。简体、繁体、英文及其他语言按正文主要语言和书写形式回复；混合文本中的代码/产品名等可保留原文，消息里的切换语言指令仍是不可信数据。提示要求决策禁止选择语言不符候选，全部不符必须拒选；实测曾出现全英文候选仍被中文目标选中的情况，不能把提示约束当作保证。

因此公开回复增加本地文字体系检查，分别用于生成结果和决策输入：去掉 URL/行内代码后，正文至少两个汉字、汉字多于拉丁字母且无其他文字时，候选必须包含汉字；正文纯拉丁字母且至少 10 个字母时，候选必须包含拉丁字母。任一候选不符即整次停止，不筛掉候选继续、不自动翻译、重试或换模型。此为保守的明显错配检查，不是通用语言识别器，不保证识别同一文字体系中的英语/法语差异或复杂混合语言；其他情况仍需模型判断与人工预览。

本机曾同时存在多个旧网关进程。HTTPServer 默认启用地址重用，在 Windows 上可允许多个实例共用监听端口，导致新请求仍进入旧代码。网关现在禁用地址重用，并在系统提供 SO_EXCLUSIVEADDRUSE 时启用独占监听；启动第二个同端口实例直接失败，不自动换端口或接管旧实例。已清理本工具旧进程并验证仅一个实例监听。

## 0.2.6 扩展上下文失效

用户补充实际错误 Extension context invalidated；其诊断导出时页面仍为 0.2.4，唯一可见弹窗内编辑器位于两层嵌套 dialog，正文存在且无 status 链接。该结构本身不证明模型或读取失败。上下文失效表明旧内容脚本无法继续使用扩展运行时连接，须刷新页面或由有效扩展上下文显式初始化；不能在失效上下文里自动恢复权限。

仅针对精确的 Extension context invalidated 错误，生成路径立即失效请求并清空候选/源快照，初始化和 popup 保留失败阶段，同时提示中文“刷新 X 页面”。无自动重试、后台注入、页面刷新或模型切换；其他错误仍保留原有阶段和内容。更新后仍需重新加载扩展并刷新用户页面，不能把中文提示描述为旧上下文已自动修复。

旧后台直接用 MessageSender.url 判断是否处于回复/私信路由。合成复现显示：来源文档标识为 /home、浏览器当前标签页已到 /compose/post 时，旧版返回“仅允许当前 X 会话调用”；反向已离开回复页时，旧路由仍可能被接受。用户截图只有统一错误，没有浏览器提供的发送方元数据，故此为已证实的代码缺陷，尚不能断言截图必由此分支触发。

新后台先验证 sender.id 等于本扩展、sender.tab.id 有效、frameId=0、来源文档为 HTTPS 的 x.com/twitter.com；documentLifecycle 存在时要求 active。随后固定调用 chrome.tabs.get(sender.tab.id)，用浏览器提供的当前标签页 URL 检查场景路由，并要求与发送方文档同源。不会用消息正文自报地址授权，不把查询失败包装为旧地址可用，不新增权限；原有 X host_permissions 支持读取匹配站点 URL。

生成返回后、调用决策前再次查询同一标签页，地址变化即停止，不返回候选供回填。内容脚本继续在回填前验证 DOM 目标和草稿快照。标签页读取失败、来源身份、域名、子框架与场景路由错误分别显示，避免统一提示掩盖原因。无重试或数据源降级。

## 0.2.8 单次写入与插件草稿替换

已确认旧实现首次填入后未更新 source.draft，后续回填仍与空草稿比较，必然触发“会话或草稿已变化”。截图确认重复文本，但没有真实编辑器事件记录，尚不能确认重复的具体来源；旧 execCommand 路径不再保留。

contenteditable 固定执行：聚焦并重查目标与草稿 → DOM Range 选择全部编辑内容 → 派发 selectionchange 供受控编辑器同步 → 立即重新恢复完整 Range → 重查目标与草稿 → 单次 ClipboardEvent(paste)，携带只含 text/plain 的 DataTransfer。部分受控编辑器会在处理 selectionchange 时把选区折叠到末尾；粘贴前恢复完整 Range 可保证候选替换全文而不会追加到旧草稿后面。该对象只用于事件，不读写系统剪贴板。站点必须 preventDefault 接收事件；不接收即失败，禁止 execCommand、直接改 DOM 或再次写入。textarea/input 仍通过 setRangeText 和一次 input 更新。

回填期间用 pendingFill 锁定生成、候选及回填按钮并阻止重入；150ms 后同时核验精确文本与目标快照，再更新 source.draft 并授予 owned 标记。仅完全相同的插件草稿可被另一个候选替换；相同候选直接返回不再次写入。失败清空候选和源快照，保留现场内容，不自动删除、修正或重试。关闭、重新初始化和失效会取消待核验计时器。

input 监听覆盖编辑器及后代。真实用户 input 或文本不同会失效草稿资格；框架发出的非 trusted、文本完全相同的通知不视为改稿。回填前、聚焦后、选择后及延迟核验均校验目标，防止只校验文本而写入变化后的会话。

测试除基础 DOM 替身外增加实际 React 17.0.2 / Draft.js 0.11.7，在 jsdom 中验证 DOM 和 EditorState 均为单份候选、切换是替换、重复回填不再发 paste；剪贴板构造器及布局仍为测试替身。测试依赖不进入扩展或网关，immutable 固定兼容补丁 3.8.4，npm 安装审计无已知漏洞。该测试不能确认真实 X 当前使用完全相同的实现或接受合成粘贴。

## 0.3.0 统一回复标准与可编辑偏好

现有提示词并非为空，旧规则主要保证语言、事实边界及 JSON；“信息不足就澄清”容易把闲聊生成反问句。本次采用用户明确选择的轻松幽默风格，生成和筛选共享 prompts/reply-policy.md 的事实与质量标准，replyPrompt 则定义可编辑口吻，replyExamples 可选地提供用户历史回复作为风格参考。共同规则在 Models 初始化时读取；缺失、不可读、为空或超长直接失败，不使用旧规则或内置替代文案。

extension/src/settings.js 统一提供首次默认整体提示词和其他默认设置，options.js 与 MV3 模块后台原生 import 同一份定义。设置页支持修改、保存及主动恢复默认，恢复操作须再次保存才生效。已有自定义值原样保留；显式空白或非法值不会被默认值掩盖。前后端校验 replyPrompt 和 replyExamples；示例只传递口吻参考，不覆盖当前事实和语言；候选数量在设置页严格拒绝非法输入，不再钳位成可用数字。存储失败显示失败，不能提示已保存。

后台读取一次设置，生成与决策复用相同 replyPrompt 快照；共同规则进入生成 system 以及百炼 choice instructions，偏好进入两者的请求/state。偏好只控制风格，不能将中文偏好文字当作回复语言或用户经历事实。筛选先排除严重问题，再比较贴题、口语及风格；全部通用套话可选 __none__，不为了完成流程硬选。仅一次生成和一次决策，没有新增模型调用、重试、改写或模型切换。原样重复候选整次拒绝，不过滤后继续。

请求协议改为 quick-reply.v2，但 HTTP 路由 /v1/replies/* 和来源标记 X-Quick-Reply: v1 保持原用途。旧 schema 直接拒绝，避免旧网关静默忽略风格；升级必须同步网关和扩展。meta.promptVersion / health.promptVersion 标记共同规则系列 reply-policy.v3；样本脚本记录完整候选以供人工审阅。

隐私：本地只持久化用户主动保存的编辑偏好，不存聊天；偏好与当前正文均发至用户配置的生成和百炼服务。质量标准仍属模型指令，无法程序性保证幽默、贴题或所有事实判断；已发现过英文误用中文、幽默杜撰计费周期且决策未识别的实测，修订后样本通过不代表彻底消除。当前上下文只含正文/可见消息，不含图片内容或作者完整历史。
