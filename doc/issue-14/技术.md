# Issue #14 技术设计：公开帖子一键回复（v2）

## 设计状态

- 原型：`原型/index.html`（v2），已评审（2026-10-20）。
- 技术方案：本文（v2），已评审（2026-10-20）。
- Issue：[xForMe/x-quick-reply#14](https://github.com/xForMe/x-quick-reply/issues/14)。
- v1 实现：主题分支 `feat/issue-14-one-click-reply` 提交 `ea40246`（点击扩展面板按钮触发）。v2 在其基础上修改，尚未开始编码。

## 需求解释与变更原因

v1 采用保守解释：用户打开回复弹窗后，还要点击扩展面板上的“生成并发送回复”。用户评审后指出这仍是两步操作，要求打开回复就自动执行，默认按百炼判断的最佳候选发送，并担心操作过快。

v2 的触发条件改为“用户点击 X 帖子上的回复按钮”。用户仍然为每条回复主动点击一次，但扩展会自动完成后续步骤。为了降低误发风险、也让节奏不过快，回填后加入可配置倒计时（默认 10 秒，可取消、可立即发送）。用户已明确：发送频率限制和随机延迟不纳入本需求。

## 已确认事实（来自当前代码）

- `content.js` 以 manifest content script 在 x.com 全站注入，面板常驻，并通过 `observeUrlChanges` 每 500 ms 同步路由及弹窗可见性。
- `autoLike.captureReplyLaunch` 已在捕获阶段监听 document click，从 `[data-testid="reply"]` 所在帖子取得状态 URL；v2 复用这个识别点作为触发信号。
- `generate()` 已串联读取、生成、决策和回填；`fillSelected({ sendAfterFill })` 回填核验通过后调用 `sendSelectedReply()`，后者只点击一次唯一可用的 `tweetButton*`，再用 5 秒窗口确认编辑器清空或卸载。
- `onInput` 在用户修改草稿时调用 `invalidate()`，会清空生成、回填和发送确认状态。
- `service-worker.js` 每次生成都会重新读取并校验 `oneClickReply`，然后随响应返回设置快照。

## 推测与待验证

- 推测：X 点击回复按钮后，弹窗通常在 1 秒内渲染；v2 设定 5 秒等待窗口，真实页面待验证。
- 推测：X 发送成功后会清空或卸载编辑器（沿用 v1 判断，真实页面待验证）。
- 待验证：用户在倒计时期间点击 X 弹窗外部或按 Esc 关闭弹窗时，现有可见性判断能否在 500 ms 内识别。

## 方案

### 配置

| 键 | 类型 | 默认 | 校验 |
| --- | --- | --- | --- |
| `oneClickReply` | boolean | `false` | 非布尔直接报错（已有） |
| `oneClickCountdownSeconds` | integer | `10` | 3–60 的整数；否则设置页拒绝保存，Service Worker 和内容脚本读取时报错停止 |

设置页文案改为“点击帖子回复后自动生成，并在倒计时后发送公开回复”，并在下方显示倒计时秒数输入框。开关关闭时禁用这个输入框，但保留原值。

### 自动触发

1. 用户点击 `[data-testid="reply"]` 时，`isTrusted === true` 才会被识别为触发；合成点击（包括扩展自身产生的点击）一律忽略。此时重新读取 `chrome.storage.local` 的 `oneClickReply`，不使用页面初始化时的缓存，以免设置刚被关闭仍自动执行。
2. 读取成功且为 `true` 时，记录一次 `autoTrigger = { statusUrl, deadline: now + 5000 }`；读取失败或类型无效时，在面板报错，不触发。
3. 路由同步循环发现唯一可用的公开回复弹窗后消费这次触发（只消费一次），调用 `generate({ trigger: "auto" })`。
4. 5 秒内弹窗未出现时丢弃这次触发，不生成，也不提示错误（用户可能只是误点）。
5. 编辑器已有内容（X 恢复了草稿）时，沿用现有校验：报错“输入框已有草稿”并停止。

不触发的情况：页面加载、路由变化、直接访问 `/compose/post`、私信、普通发帖、引用帖。

### 生成、决策与回填

沿用 v1：一次生成、一次决策。百炼拒选（`reviewRequired`）时停止，不回填。回填仍走受控编辑器路径并核验，失败即停止。

### 面板主按钮（评审决定：手动逻辑）

面板主按钮无论一键开关是否开启，都只“生成并填入回复”，由用户手动点击 X 的回复按钮发送，恢复 issue #14 之前的行为。v1 中“点击面板按钮即发送”的路径取消。适用场景：直接打开 `/compose/post`、刷新回复页、自动触发失败或取消后重新生成。只有“可信回复按钮点击”这一种触发会自动发送。

### 倒计时

回填核验通过后，若 `oneClickReply === true` 且场景为 `public-reply`，进入倒计时状态：

```text
countdown = { source, text, deadline: now + seconds*1000, timer }
```

- 面板显示剩余秒数、选中文本和两个按钮：“立即发送”和“取消发送”。每 250 ms 刷新一次显示，以 `deadline` 为准，不累加计数。
- 到期或点击“立即发送”时，先调用 `sourceIsCurrent(text)` 再核验一次，然后调用 `sendSelectedReply()`；核验失败就停止。
- 以下任一情况都会取消倒计时：
  - 点击“取消发送”或关闭面板；
  - 编辑器内容变化（`onInput` → `invalidate`）；
  - 路由变化或弹窗不再可见。

  取消时不发送、不清空草稿，只显示具体原因，例如“已取消自动发送（回复弹窗已关闭），草稿已保留，请手动检查后发送”。
- 页面切到后台（评审决定）：不取消，倒计时继续，到期照常再核验并发送。Chrome 会把后台标签页的定时器限制到约 1 秒一次；因为以 `deadline` 判断，最多晚 1 秒左右。后台标签页能否触发 X 发送，待真实页面验证。
- 切换候选（评审决定）：把这次选择当作确认，停止倒计时，走现有“替换插件刚写入且未修改的草稿”路径回填新候选；核验通过后立即调用 `sendSelectedReply()`，不重新倒计时。回填或核验失败则停止，不发送。发送中（已点击回复）禁止切换候选。
- 取消后不会自动恢复倒计时；用户可以手动点 X 的“回复”，或在面板重新生成并填入。

### 发送与确认

沿用 v1 `sendSelectedReply()` 与 5 秒确认：只点击一次，确认失败不重试；同时开启自动点赞时由其控制器接管确认流程。

### 状态与文案

| 阶段 | 面板状态文案 |
| --- | --- |
| 自动触发 | 已打开回复，正在自动生成回复并选择合适内容… |
| 百炼拒选 | 百炼未选择合适回复，未发送，请人工起草 |
| 倒计时 | 将在 N 秒后发送，可取消 |
| 取消 | 已取消自动发送（原因），草稿已保留，请手动检查后发送 |
| 发送中 | 已点击回复，正在等待 X 确认发送… |
| 成功 | 回复已发送，页面已确认 |
| 失败 | 一键发送未确认/失败原因，草稿已保留，未自动重试 |
| 设置无效 | 一键回复倒计时设置无效（需 3–60 秒整数），请重新保存扩展设置 |

## 失败和停止条件

- 设置读取失败或类型、范围非法：停止，不用默认值替代。
- 触发后弹窗不唯一、目标不唯一或正文非法：沿用 `readPublicReplyContext` 报错并停止。
- 生成或决策失败、协议不符、超时：停止，不重试，不切换模型。
- 倒计时取消条件发生，或到期再核验失败：不发送。
- 发送按钮不唯一或不可用、确认超时：停止，不点击第二次。

## 权限与隐私

不新增 manifest 权限。设置只存于 `chrome.storage.local`；倒计时不记录帖子正文或草稿。现有 auto-like 调试日志不变。

## 测试

自动化测试（jsdom + 测试替身，仅在测试中使用）：

- 默认关闭时点击回复按钮不触发生成；开启后只有可信点击会触发，合成点击不触发。
- 触发后弹窗出现只生成一次；5 秒未出现则不生成。
- 倒计时到期只点击一次发送；“立即发送”提前发送且只点击一次。
- 每个取消条件都不发送、草稿保留：“取消发送”按钮、输入变化、路由变化、弹窗关闭、关闭面板。
- 页面隐藏时不取消，到期发送一次。
- 倒计时中切换候选：替换回填新候选并立即发送一次；替换核验失败时不发送。
- 面板主按钮在一键开关开启时也只生成并填入，不点击发送。
- 到期再核验失败时不发送。
- 倒计时设置 2、61、非整数或非数字时，设置页拒绝保存，Service Worker 报错。
- 私信、`/compose/post` 直接访问不触发；百炼拒选不回填不发送。

运行：`npm test`；`python -X utf8 -m unittest discover -s tests -v`（网关未改，回归用）。

真实验收边界：自动化测试不能证明 X 生产 DOM 的回复按钮选择器、弹窗渲染时机和发送确认信号。真实验收需用户在获准账号与帖子上完成，记录版本、场景、各阶段结果。

## 上线与回滚

以 0.5.0 加载已解压扩展。回滚：关闭设置中的一键回复开关（立即生效，因为每次点击回复都会重新读取设置），或重新加载 0.4.4 版本。

## 风险

- 自动触发会提高误发风险；倒计时、可取消和到期再核验是主要缓解措施。
- 不做频率限制，连续快速回复的平台风险由用户自行承担（用户已知悉并决定不纳入）。
- X DOM 变化可能导致触发或发送失败，此时会停止并报错，不会误发到其他目标。

## 评审结论（2026-10-20）

1. 倒计时范围为 3–60 秒整数，默认 10，不允许 0。
2. 页面切到后台：倒计时继续，到期发送。
3. 倒计时中切换候选：回填新候选后立即发送。
4. 直接打开 `/compose/post` 等情况不自动触发；面板主按钮恢复为只生成并填入，手动发送。
5. 真实验收：使用 Chrome 中已登录的 X 账号，同时开启自动点赞。帖子由用户在验收时选定。
