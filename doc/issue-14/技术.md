# Issue #14 技术设计：公开帖子一键回复

## 设计状态

- 原型：`原型/index.html`，已产出，待评审。
- 技术方案：本文，已产出，待评审。
- Issue：[xForMe/x-quick-reply#14](https://github.com/xForMe/x-quick-reply/issues/14)。

## 需求解释

Issue 原文只写了“新增开关改成一键操作”，没有明确要求打开帖子后无人触发发送。本文采用可审计的保守解释：用户主动点击扩展面板的“生成并发送回复”一次，扩展才执行生成、选择、回填和发送；打开帖子、打开回复弹窗、路由变化都不会自动发送。该开关只适用于公开帖子回复，私信继续生成并回填，用户手动发送。

这样能消除“点击生成”和“再点击回复”两个动作，同时保留一次明确的用户外部写操作确认。若用户实际需要“打开回复弹窗后自动发送”，应另立需求，因为它会改变触发条件、误发风险和验收范围。

## 已确认事实

- 当前扩展已经把生成候选、百炼选择和候选回填串成一次“生成”操作，但发送按钮仍由用户点击。
- 当前 `autoLikeAfterReply` 是独立设置，只有页面确认用户发送后才执行点赞流程。
- 当前回填会比较页面、目标帖子、编辑器和草稿快照；失败会停止，不自动重试或改写现场。
- 当前真实 X DOM、发送事件和平台行为没有被本地测试完全证明。

## 方案

### 配置

在 `extension/src/settings.js` 增加 `oneClickReply: false`。设置页增加明确的开关和警示文案，保存时只保存布尔值。缺失或非布尔值直接报错，不默认开启。

### 流程

1. 用户打开公开帖子回复弹窗，点击扩展面板主按钮。
2. 内容脚本读取唯一目标帖子和唯一编辑器；编辑器有草稿、目标变化或上下文无效时停止。
3. Service Worker 按现有协议调用生成和决策网关，并返回 `oneClickReply` 的设置快照。
4. 决策拒选、候选非法、协议错误、网关失败或页面导航变化时停止，不回填、不发送。
5. 选中候选按现有受控编辑器路径回填，等待框架渲染后精确核验文本、目标和草稿。
6. 仅当 `oneClickReply === true` 且场景为 `public-reply` 时，在同一回复弹窗中寻找唯一可用的 `tweetButton*`；找不到、多个候选或按钮禁用时停止并保留草稿。
7. 调用一次 `click()`，随后最多等待 5 秒确认编辑器清空或卸载。确认成功显示“回复已发送”；超时显示失败，不自动重试。
8. 若同时开启自动点赞，发送点击仍由既有 `autoLikeAfterReply` 控制；一键回复本身不改变点赞协议。

### 失败和停止条件

- 一键模式开关读取失败、类型错误或保存失败：停止。
- 私信场景：不自动发送，保留现有生成和回填行为并提示范围限制。
- 发送按钮不唯一、不可用、弹窗/目标变化、草稿变化、路由变化或发送确认超时：停止，报告阶段和原因，不点击第二次。
- 不增加模型调用、不切换服务商、不重试、不用缓存或固定文案替代真实结果。

## 文件与契约变更

| 文件 | 变更 |
| --- | --- |
| `extension/src/settings.js` | 新增默认关闭的 `oneClickReply` |
| `extension/src/options.js` | 读取、校验、保存开关并显示风险提示 |
| `extension/src/content.js` | 主按钮文案、回填后一次性发送、发送确认和停止逻辑 |
| `extension/src/service-worker.js` | 校验并回传 `oneClickReply` 设置快照 |
| `tests/*.cjs` | 覆盖默认关闭、公开回复一次发送、私信不发送、失败不重试、发送确认超时 |

网关请求协议不增加字段：该开关是本地浏览器动作策略，不应发送给模型或百炼。

## 验收边界

- 自动化测试可证明设置持久化、一次点击调用链、按钮只点击一次、失败停止和私信边界。
- 自动化测试不能证明当前 X 生产 DOM 一定接受选择、粘贴、发送或“编辑器清空/卸载”作为发送确认。
- 真实验收必须在用户确认的 X 页面完成，并记录扩展版本、场景、成功/失败阶段；不把单次页面成功写成平台兼容性保证。

## 初始化与并发约束

内容脚本初始化后先读取 `chrome.storage.local.oneClickReply`。读取完成前主按钮显示“读取设置中…”，但点击会等待这次读取结果；读取失败或类型无效时不发起生成。这样不会把默认关闭的视觉文案误当成已确认设置，也不会在读取失败时隐式降级。

生成响应返回的设置快照仍会再次校验并用于本次操作。`autoLikeAfterReply` 在同一响应中先完成配置，再触发一键发送；自动点赞控制器因此可以接管同一次发送确认，避免一键回复和自动点赞各自建立确认轮询器。
