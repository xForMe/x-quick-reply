# Issue #14 技术方案补充草稿

> 本文件仅供用户评审和后续粘贴到 GitHub Issue；尚未发布到 GitHub。

## 背景

当前扩展可以生成候选、调用百炼选择并回填回复草稿，但用户仍需再次点击 X 的公开回复按钮。Issue #14 希望把这段公开回复路径收敛为一次扩展操作。

## 方案摘要

- 设置页新增默认关闭的“一键生成并发送公开回复”。
- 用户主动点击扩展面板主按钮后，执行读取、生成、决策、回填核验，再点击一次唯一可用的公开回复按钮。
- 打开帖子或回复弹窗不会自动发送；私信不自动发送。
- 编辑器清空或卸载视为发送迹象，最多等待 5 秒；无法确认就停止且不重试。
- 自动点赞保持独立开关，并复用同一次发送确认。

## 文档入口

## 范围与非目标

范围是公开帖子回复弹窗的一次生成、选择、回填和发送。非目标包括打开页面即发送、私信自动发送、批量操作、自动重试、模型切换以及绕过 X 平台限制。

## 验收标准

默认关闭；开启后公开回复只发生一次发送点击；发送确认失败不重试；私信不自动发送；自动化测试通过；真实 Chrome/X 验收记录单独补充。

## 风险与待决问题

- X 当前生产 DOM 的发送按钮选择器和编辑器卸载行为尚未由真实页面验证。
- 需要用户确认“一键”的触发定义、私信范围和发送确认信号。
- 外部写操作仍受 X 平台规则、账号权限和页面状态影响。
