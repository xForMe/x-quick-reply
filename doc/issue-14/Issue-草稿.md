# Issue #14 技术方案补充草稿

> 本文件仅供用户评审和后续粘贴到 GitHub Issue；尚未发布到 GitHub。

## 背景

当前扩展可以生成候选、调用百炼选择并回填回复草稿，但用户仍需再次点击 X 的公开回复按钮。Issue #14 希望把这段公开回复路径收敛为一次扩展操作。

## 方案摘要（v2，2026-10-20 用户评审后修订）

- 设置页的“一键回复”默认关闭；新增发送前倒计时，3–60 秒整数，默认 10 秒。
- 开启后，用户点击帖子“回复”按钮（可信点击）、弹窗出现时自动生成，并按百炼选中候选回填核验。
- 回填后显示倒计时、选中文本、“立即发送”和“取消发送”；到期再核验通过后，只点击一次回复按钮。
- 编辑草稿、关闭弹窗、切页或关闭面板都会取消发送并保留草稿；页面转后台时倒计时继续；切换候选后回填并立即发送。
- 面板主按钮只生成并填入，由用户手动发送；直接打开 `/compose/post` 不自动触发。
- 百炼拒选、生成失败、发送确认超时（5 秒）时停止，不重试；私信不自动发送；不做频率限制和随机延迟（用户决定）。

## 范围与非目标

范围是由用户点击帖子“回复”触发的一次生成、选择、回填、倒计时和发送。非目标包括页面加载或直接打开回复链接即发送、私信自动发送、批量操作、频率限制与随机延迟、自动重试、模型切换以及绕过 X 平台限制。

## 验收标准

默认关闭；开启后点击帖子回复即自动生成，倒计时可取消，公开回复只发生一次发送点击；发送确认失败不重试；私信不自动发送；自动化测试通过；真实 Chrome/X 验收记录单独补充。

## 风险与待决问题

- X 当前生产 DOM 的发送按钮选择器和编辑器卸载行为尚未由真实页面验证。
- 需要用户确认“一键”的触发定义、私信范围和发送确认信号。
- 外部写操作仍受 X 平台规则、账号权限和页面状态影响。
