# 部署与回滚

## 环境与配置

需要 Chrome MV3、Python 3.10+。网关只用 Python 标准库，无第三方安装依赖；Node 仅用于开发检查。

在 .env 填写配置，参考同目录 .env.example：

- LLM_BASE_URL：生成服务的 OpenAI 兼容 Base URL，包含服务要求的版本路径（例如 /v1），不含 /chat/completions。
- LLM_MODEL：该服务实际支持的模型名。
- LLM_API_KEY：生成服务凭据，不贴入聊天或提交仓库。
- LLM_JSON_MODE：服务明确支持 response_format=json_object 时可设 true；默认 false，但始终要求并严格解析 JSON。
- DECISION_PROVIDER：普通百炼 API 填 bailian，Token Plan 填 bailian-token-plan。
- BAILIAN_SYSTEMONE_URL：普通 API 的完整 System One 地址，含业务空间 ID、地域及 /compatible-mode/v1/systemone。
- DASHSCOPE_API_KEY：普通百炼 API 密钥。
- BAILIAN_TOKEN_PLAN_API_KEY：仅 Token Plan 使用的专用密钥，网关地址由程序固定。
- MODEL_TIMEOUT_SECONDS 默认 25；QUICK_REPLY_PORT 默认 8787。进程环境优先，修改后重启。

本机 .env 的具体配置项已由用户填写，2026-10-17 模型请求与本机网关串联实测成功；.env.example 仍保留脱敏空值。不引用其他 Skill 或外部配置文件。修改配置后仍需重新验证。

2026-10-17 经用户明确要求，当前本机 LLM_MODEL 已切换为 gpt-6-luna，网关已重启，并通过中英合成帖的实际 HTTP 生成及决策验证。扩展代码未改，无需重新加载扩展；决策仍为 decision-model-preview。若用户要求切回原模型，显式将 LLM_MODEL 改为 gpt-6.1-sol、重启网关并重新验证，不在失败时自动切回。

## 0.3.0 整体提示词更新

本版必须重启网关并重新加载扩展到 0.3.0，刷新 X 后使用；请求协议 quick-reply.v2 与旧版不兼容。网关程序旁须保留 prompts/reply-policy.md，不能只复制 gateway.py。共同规则不可读时启动明确失败，不自动使用旧版规则。health 应显示 schemaVersion=quick-reply.v2、promptVersion=reply-policy.v3。

扩展设置新增“整体回复提示词”，首次缺字段使用已定义的自然聊天默认偏好；已有自定义偏好保留，不覆盖。可选填写用户历史回复示例，最多 3000 字符，只用于学习口吻。编辑后保存，下次生成生效，不需重启网关；主动恢复默认也须再保存。只修改共同规则文件时须重启网关。

真实接口合成样本见 提示词样本验证.md；真实 X 设置页面和编辑器仍需人工验收。回滚必须同时回滚扩展和网关的兼容版本，并保留本机 .env 与用户草稿；不能把 v2 请求交给旧网关。共同规则版本升级为 reply-policy.v3。

## 启动与加载

1. 从仓库根目录执行 python gateway.py。也可从任意目录用 gateway.py 绝对路径运行，配置独立于启动目录。
2. 打开 chrome://extensions，开启开发者模式，加载已解压目录 extension。工具根目录包含 Python 缓存及网关配置，不作为浏览器扩展加载目录。
3. 在扩展选项保存 http://127.0.0.1:8787、语气和候选数量。旧版存过空地址时需重新保存；本版无 Mock 降级。
4. 公开回复：回原帖详情页刷新，再点原帖回复按钮打开带原帖正文的弹窗；不要直接打开 /compose/post。私信：刷新具体会话。右下角面板点击生成，也可点工具栏图标打开面板。内容发送至配置的生成服务和百炼；选中后尝试回填空输入框，用户检查后发送。
5. 消息/输入框无法可靠识别时停止并检查适配，不扩大采集范围。真实 Chrome/X 适配待验收。

## 故障处理

0.2.7 历史修复后台当前路由校验：在 chrome://extensions 重新加载并确认 0.2.7，回到 X 刷新网页，再从帖子回复按钮打开弹窗并生成。本次只改扩展，无需重启 gpt-6-luna 网关，也不新增权限。若再失败，保留新版具体报错；它会区分来源身份、标签页读取、域名/框架或当前路由问题，不再统一显示“仅允许当前 X 会话调用”。

0.2.6 仅更新扩展的失效连接提示：在 chrome://extensions 重新加载插件并确认 0.2.6，然后回 X 网页按 F5，再重新打开原帖回复弹窗并生成。若报 Extension context invalidated，需要刷新的是 X 网页，不能只反复点扩展重新加载。网关已使用 gpt-6-luna，本次无需重启网关或改模型配置。

当前 0.2.5 升级须同步更新网关和扩展：重启 gateway.py，重新加载扩展并确认 0.2.5，点击插件图标初始化页面后再生成。语言策略固定为按正文识别；旧版固定 language 值会被网关明确拒绝。模型配置不自动变更；修改 LLM_MODEL 后需单独重启网关并验证。

同一端口只允许一个网关实例；新版独占本机监听端口，第二个实例启动失败，不会改用其他端口。升级前停止旧服务，避免 Windows 地址重用使新旧代码混杂接收请求。本次已清理本工具旧进程、启动新版并通过 HTTP 语言校验和合成中文生成/决策测试。

- 缺少 LLM_*：填写生成服务配置并重启。
- 百炼 HTTP 401/403：核对密钥、业务空间和模型权限，普通 Key 与 Token Plan Key 不混用。
- HTTP 402/429：核对服务额度和限流，不通过更换身份绕过。
- 生成 JSON 无效：核对模型输出格式和截断情况，插件不回填部分结果。
- 拒选、草稿或会话变化：人工起草或重新生成。

网关只监听 127.0.0.1，校验 Host 和扩展 Origin；不隔离同机其他进程/扩展，仅适用于可信单用户设备，不部署公网。

## 回滚

Ctrl+C 停止网关，在扩展页停用或移除插件。更新后重新加载扩展并刷新 X 页面。不会自动清空已有草稿，也不会回滚用户手动发出的消息；服务商凭据撤销需在控制台单独处理。
