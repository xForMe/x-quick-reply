# 快速回复插件需求

## 目标与范围

用户在 Chrome 打开 X 的帖子回复弹窗或具体私信会话，主动点击生成：OpenAI 兼容大模型起草 2–5 条候选，阿里云百炼 decision-model-preview 选择合适回复，再自动回填到空输入框，用户检查并手动发送。

0.2.0 补充用户截图中的公开帖子回复弹窗：仅读取弹窗内唯一目标帖正文和唯一回复框，不使用背景信息流。还支持 /i/chat/<id> 和 /messages/<id>。不支持普通发帖、引用帖、纯图片/多正文帖子、详情页内联回复或其他网站。真实 X 页面兼容性尚未验证。

## 已确认选择

- 决策使用阿里云，参考用户指定 decision-ai Skill，实现 System One choice。
- 生成使用用户选择的“其他 OpenAI 兼容接口”，不静默改为通义千问。
- 生成与决策的具体配置项直接在工具配置中填写，不引用其他配置文件；用户已填充，并于 2026-10-17 验证两类 API 及本机网关串联请求成功。
- 点击生成后读取、生成、选择、回填；不实现后台循环、批量私信或自动发送。

## 输入输出

- 最近可见最多 20 条消息，每条最多 800 字符、总计 8,000 字符；不读取隐藏会话、全量历史或其他标签页。
- 无法识别说话人时标注 unknown，不把全部消息假定为对方发言。
- 输出候选、选择、原始概率及置信度；置信度不是回复正确率。
- 全部候选不合适时允许拒选，停止回填并提示人工起草。

## 验收标准

1. 仅已识别的帖子回复弹窗或具体私信会话可以触发生成；普通页面来源不可访问模型网关。工具栏图标提供可见入口，从首页经 SPA 导航打开回复也能显示面板。
2. 大模型一次生成指定数量候选；JSON 非法、截断或数量不符则整次拒绝。
3. 生成成功后调用百炼，从候选及“不合适”中选择；不虚构自由文本理由或正确率。
4. 合法选择后自动尝试回填空输入框；不点击发送、不覆盖原草稿。
5. 生成期间切换会话、消息变化、修改草稿或编辑框变化后拒绝回填旧结果。
6. 缺配置、HTTP 失败、超时或非法响应时明确报错，不切换供应商、不用 Mock 替代。
7. 密钥仅留在网关配置；不把聊天、密钥、完整响应写入仓库、扩展存储或日志。
8. 公开回复必须保留完整的唯一正文（不超过 800 字符），候选最多 280 字符；超限报错，不截断凑成功。生成和决策都必须收到 public-reply 场景，不能套用私信提示词。
9. 当前回复预览没有帖子链接时仍可依据同一弹窗内的唯一正文与输入框读取；不从背景帖子或路由推测目标。回填前验证弹窗、目标、正文节点、编辑器及内容快照，变化或歧义时停止；隐藏输入框不计为第二个可用目标。
10. 公开回复语言必须与目标帖正文的主要语言和书写形式一致，不受 X 界面、浏览器或系统提示语言影响；专有名词可保留原文。生成和决策使用同一规则，语言不符的候选不可选；全部不符时拒选，不自动翻译、补写或切换模型。
11. 从首页经站内导航打开回复时，后台按 Chrome 查询到的当前发送方标签页路由授权；仍须是本插件、X 同源顶层文档。标签页无法查询、已离开回复/私信页面或生成中切换地址时停止，不以来源文档的旧路由或消息自报地址替代。
12. 首次回填核验成功后，可切换候选并替换插件刚写入且完全未修改的草稿；同一候选重复回填不再次写入。手动修改、目标变化或核验失败后停止并取消替换资格，不覆盖用户草稿。单次回填只触发一次编辑器写入，不自动重试或混用写入机制。

## 待完成依赖

## 0.3.0 整体回复提示词

用户认为回复内容质量不足，并明确选择“轻松幽默，像日常聊天”。提供可编辑整体提示词，默认短句、口语、贴具体内容接话；不硬凑笑点，不把闲聊变咨询，不泛泛安慰或劝坚持，严肃处境保持得体。偏好不能覆盖正文语言和事实边界。

验收：设置保存后下次生成生效，生成/筛选收到完全相同的偏好；修改或主动恢复默认可见且需保存；空白/超长/存储失败明确停止；原样重复候选整次拒绝；全部不合适允许拒选。保持一次生成加一次决策，不增加重试或改写调用。以合成日常、严肃、英文与通用套话负样本做真实接口测试，风格质量仍需用户人工认可，不能仅由 JSON/概率判定。
